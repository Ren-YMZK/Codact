## 次の大方針：「作りながら学ぶ」体験への進化

目指す体験：「勉強して、書いて、レビューもらって改善してたら、気づいたら小さなアプリができていた」。  
文法問題集から「実際の開発に近い体験」へ。ターゲットは初学者をIT企業に入れるレベルにすること。

### 現状の構造（重要な前提）

- 今のLessonは「ストーリーは繋がっているがコードは独立」した練習問題集。  
  各Lessonは白紙または問題設定からスタートし、前回書いたコードは引き継がれない。
- `levels.built` / `next_preview` に「各Levelで何ができあがるか」の物語は既にある  
  （＝積み上がりの設計図は存在するが、コードとしては積み上がっていない）。

### 決まった方針：強度2 → 将来強度3

- **強度2**：各Lessonの初期コードに「前回までの完成コード」が入り、その続きに機能を足していく。  
  最後に全部入りのコードができあがる。
- **将来 強度3**：最後に「自分が作った動くアプリ」が手元に残る。

### コード引き継ぎ方式：案イ + 将来案ウ

- **案イ（採用）**：Lesson N の初期コード = Lesson N-1 の模範解答を引き継ぐ。  
  ユーザーの自由なコードではなく模範解答を引き継ぐことで問題設計の整合性を保つ  
  （ユーザーの書き方が次の指示と噛み合わない破綻を防ぐ）。
- **将来 案ウ**：「自分が前回書いたコードを振り返る」機能で本物感を補う。

### データ設計（案1で合意・未実装）

- `lessons` テーブルに `solution_code`（模範解答＝そのLessonまでの完成形）を追加する。
- ルール：Lesson N の `initial_code` = Lesson N-1 の `solution_code` + 今回書く部分のヒントコメント。
- 各Lessonが「それまでの完成形」を丸ごと持つ（多少重複してもシンプルさを優先）。

### ファイル分割（将来論点・今は棚上げ）

- 今の基礎文法は1ファイルが育つ形でOK。採点も1ファイルのまま。
- 将来 React/Laravel 等でファイル間連携を教える際は、関連ファイルの表示と  
  複数ファイル採点（メイン+依存ファイルを Judge0 に渡す）が必要になる。  
  今は実装しないが、データ構造を将来複数ファイルに拡張しやすい形にする意識は持つ。

### 全体像・現在地の表示（未設計）

- `built` / `next_preview` を活かし「アプリ全体の構成マップ + 今どこを作っているか」を表示したい。  
  どの画面でどう見せるかのUIは未設計。

## 再開時の最初の一歩（合意済みの進め方）

130 Lesson 全部を一度に作り直さない。1つのLevelで試作する。

1. Pythonコースの短めのLevelを1つ選び、積み上がる形に作り直す  
   （作問はブラウザの Claude Opus で。変数名・構造を全Lessonで一貫させる）。
2. Codact側でそのLevelに対し「前回コードの引き継ぎ + 全体像/現在地表示」を実装。
3. 小さく動かして体験を検証 → 良ければ全Levelへ展開。

### 作業が2種類に分かれる

| 作業 | 担当 |
|---|---|
| Codact実装（`solution_code` カラム追加・初期コード引き継ぎ・全体像/現在地UI） | Claude + Claude Code |
| コンテンツ再設計（Lessonを積み上がる形に作り直す） | オーナーが Opus で作問（量が多い） |
